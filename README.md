# Визуализатор графа зависимостей NuGet (вариант 18)

CLI-инструмент для построения графа зависимостей пакетов .NET (NuGet).
Готовые менеджеры пакетов и библиотеки для получения зависимостей
не используются. Внешних зависимостей нет, нужен Python 3.10+.

## Запуск
```
run.bat [config.xml]        # Windows
./run.sh [config.xml]       # Linux / Git Bash
```
По умолчанию используется `config.xml` в текущем каталоге.

## Тесты
```
python -m unittest discover -s tests -v
```

## Этап 1. Конфигурация
Параметры задаются в XML-файле:
```xml
<config>
    <package>Serilog</package>
    <repository>https://api.nuget.org/v3-flatcontainer/</repository>
    <test_mode>false</test_mode>
    <output>graph.svg</output>
    <ascii_tree>true</ascii_tree>
    <filter></filter>
</config>
```

| Параметр     | Описание                                   | Проверка                                  |
|--------------|--------------------------------------------|-------------------------------------------|
| `package`    | имя анализируемого пакета                  | не пустое, `A-Z a-z 0-9 . _ -`, до 100 символов |
| `repository` | URL репозитория или путь к тестовому файлу | http(s)-URL, в тестовом режиме - существующий файл |
| `test_mode`  | режим работы с тестовым репозиторием       | `true` / `false`                          |
| `output`     | имя файла с изображением графа             | не пустое, расширение `.svg`              |
| `ascii_tree` | вывод зависимостей в виде ASCII-дерева     | `true` / `false`                          |
| `filter`     | подстрока для исключения пакетов           | необязательный; допустимые символы        |

При запуске все параметры выводятся в формате `ключ=значение`.
При ошибках выводится список **всех** найденных проблем, код выхода 1.

Демонстрация: `scripts\demo_stage1.bat` (примеры в папке `configs`).

## Этап 2. Сбор данных
Прямые зависимости пакета извлекаются из репозитория NuGet (API v3)
без менеджеров пакетов и сторонних библиотек:

1. `GET {repository}/{id}/index.json` - список версий, выбирается
   последняя стабильная (без суффикса `-beta`, `-rc` и т.п.);
2. `GET {repository}/{id}/{version}/{id}.nuspec` - описание пакета (XML);
3. из `.nuspec` извлекаются все `<dependency id="..." version="...">`;
   зависимости разных целевых платформ (`<group targetFramework>`)
   объединяются без повторов.

В `repository` можно указать адрес flat container
(`https://api.nuget.org/v3-flatcontainer/`) или служебный индекс
`https://api.nuget.org/v3/index.json`: тогда адрес хранилища
пакетов (`PackageBaseAddress`) берётся из него.

Пример вывода:
```
Package: Serilog 4.4.0
Direct dependencies (3):
  System.Diagnostics.DiagnosticSource 8.0.1
  System.Threading.Channels 8.0.0
  System.ValueTuple 4.5.0
```

Обрабатываемые ошибки: пакет не найден (HTTP 404), нет связи
с сервером, некорректный ответ (JSON/XML).

В тестовом режиме (`test_mode=true`) зависимости читаются из файла
вида `A: B C` (пакеты - заглавные латинские буквы).

Демонстрация: `scripts\demo_stage2.bat`.

## Этап 3. Граф зависимостей
Граф строится с учётом транзитивных зависимостей обходом в глубину
(DFS) **без рекурсии**: вместо рекурсивных вызовов используется явный
стек, поэтому длинные цепочки не упираются в ограничение глубины
рекурсии Python.

- Уже посещённые пакеты повторно не обрабатываются: общая зависимость
  загружается один раз, циклы не приводят к зацикливанию.
- Циклы находятся отдельным обходом DFS (тоже без рекурсии) и
  выводятся в виде `A -> B -> C -> A`.
- Пакеты, имя которых содержит подстроку `filter` (без учёта
  регистра), в граф не попадают.
- Зависимость, отсутствующая в репозитории, выводится в списке
  `Not found in repository`, обход продолжается.

Пример (`configs/graph_filter.xml`):
```
Dependency graph of A (DFS order):
  A -> B, C, D
  B -> E
  E -> (none)
  C -> G
  G -> A
  D -> H
  H -> (none)
Packages: 7, dependencies: 7
Cycle: A -> C -> G -> A
Excluded by filter 'F': F
```

### Тестовые репозитории (папка `repos`)
Формат: `ПАКЕТ: ЗАВИСИМОСТИ`, пакеты - заглавные латинские буквы.

| Файл            | Случай                                   |
|-----------------|------------------------------------------|
| `simple.txt`    | ромб: A -> B, C; B, C -> D               |
| `cycle.txt`     | цикл A -> B -> C -> A                    |
| `self_loop.txt` | пакет зависит сам от себя                |
| `complex.txt`   | 8 пакетов, общие зависимости, цикл       |
| `missing.txt`   | зависимость Z не описана в репозитории   |

Демонстрация: `scripts\demo_stage3.bat`.

## Этап 4. Обратные зависимости
Режим включается ключом `--reverse`:
```
run.bat configs\reverse_simple.xml --reverse
```
Выводятся пакеты, которые зависят от заданного (напрямую
и транзитивно). Сначала по всем пакетам тестового репозитория строится
обратный индекс (ребро `A -> B` превращается в `B -> A`), затем
используется тот же итеративный DFS (`build_graph`), что и на этапе 3:
фильтр по подстроке и обработка циклов работают так же.

Пример (`repos/simple.txt`, пакет `D`):
```
Reverse dependencies of D (DFS order):
  D <- B, C
  B <- A
  A <- (none)
  C <- A
Packages depending on D (3): B, A, C
Cycles: none
```

Режим доступен только при `test_mode=true`: в NuGet сотни тысяч
пакетов, и API v3 не позволяет узнать, кто зависит от пакета,
без скачивания описаний их всех.

Демонстрация: `scripts\demo_stage4.bat` (конфигурации `configs\reverse_*.xml`).

## Этап 5. Визуализация
В обычном режиме (без `--reverse`) после вывода графа программа:

1. формирует текстовое представление графа на языке Graphviz (DOT)
   и выводит его на экран;
2. сохраняет его в файл рядом с изображением (`examples/serilog.dot`)
   и вызывает программу `dot` из Graphviz, которая строит SVG-файл,
   указанный в параметре `output`;
3. если `ascii_tree=true`, выводит зависимости в виде ASCII-дерева.

Корневой пакет закрашен, рёбра циклов - красные, пакеты, которых нет
в репозитории, - пунктиром. В ASCII-дереве пакет, уже показанный
выше, повторно не раскрывается и помечается `(*)`, возврат по циклу
помечается `(cycle)`. Дерево выводится обходом без рекурсии.

Нужен установленный Graphviz (https://graphviz.org/download/),
команда `dot -V` должна работать в терминале. Если Graphviz не
установлен, выводится понятная ошибка.

Пример (`configs/viz_complex.xml`):
```
Graphviz (DOT):
digraph dependencies {
    rankdir=LR;
    node [shape=box, style=rounded, fontname=Arial];
    "A" [style="rounded,filled", fillcolor=lightblue];
    ...
    "A" -> "C" [color=red];
    "C" -> "G" [color=red];
    "G" -> "A" [color=red];
    "D" -> "H";
}
Saved: examples/complex.dot, examples/complex.svg
ASCII tree:
A
|-- B
|   |-- E
|   \-- F
|       \-- H
|-- C
|   |-- F (*)
|   \-- G
|       \-- A (cycle)
\-- D
    \-- H (*)
```

Демонстрация для трёх пакетов NuGet (Serilog, Microsoft.Extensions.Logging,
Polly) и двух тестовых графов: `scripts\demo_stage5.bat`.
Готовые изображения лежат в папке `examples`.

Для Microsoft.Extensions.Logging и Polly задан `filter=NETStandard`.
Без него граф разрастается до ~90 пакетов и ~470 рёбер и становится
нечитаемым: старый пакет `System.ComponentModel.Annotations` для
платформ `netstandard1.x` зависит от `NETStandard.Library`, а тот -
от сотни мелких пакетов `System.*`. Для `net8.0` NuGet их не
подключает: они уже входят в .NET.

### Сравнение со штатными инструментами NuGet
Штатные средства: вкладка **Dependencies** на nuget.org,
`dotnet list package --include-transitive` (для проекта),
NuGet Package Explorer. Расхождения с нашим графом:

- **Целевые платформы.** NuGet выбирает одну группу зависимостей под
  платформу проекта (например, `net8.0`), а мы объединяем группы всех
  платформ. Поэтому у нас пакетов больше: например, для `net8.0`
  пакеты вроде `System.ValueTuple` не нужны, они входят в сам .NET.
- **Версии.** Мы берём последнюю стабильную версию каждой
  зависимости. NuGet берёт минимальную версию, подходящую под
  диапазон (`>= 8.0.1` - значит 8.0.1), поэтому у старой версии могут
  быть другие зависимости.
- **Вид результата.** `dotnet list package` выдаёт плоский список
  пакетов без связей «кто от кого зависит», а nuget.org показывает
  только прямые зависимости. Наш инструмент строит полный граф.
- **Фильтр.** Пакеты с подстрокой `filter` у нас отбрасываются,
  в штатных инструментах такой настройки нет.
